## AI Summary

An IDOR vulnerability in a healthcare website allowed non-medical users to view the shot records of people who were not their sponsors. The vulnerability was caused by a function that allowed sponsors to view their sponsored individuals' shot records in PDF form. By incrementing or decrementing the ID parameter by 1, the application would throw an HTTP Status Code 302 and redirect the user back to the endpoint, but with the PDF of the incremented ID attached in the body of the 302 requests. This allowed users to extract shot records without being associated with medical. The vulnerability led to the disclosure of PHI/PII.
