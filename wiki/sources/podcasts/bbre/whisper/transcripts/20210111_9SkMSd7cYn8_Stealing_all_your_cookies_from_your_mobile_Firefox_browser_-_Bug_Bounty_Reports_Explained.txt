When looking for mobile vulnerabilities with big impact, one of the things you need to check
is how the application uses custom URIs. On Android there are URIs with content protocol.
They allow reading one application's file or data from the other one. An example of such URI looks
like this. The first part is called content provider and it indicates what application will be used to
handle this URI. In this case it will be mobile Firefox browser. And the second part is the path of a file
that will be opened. And as you saw on the example, mobile Firefox browser allowed reading local files
using those content URIs. But after opening such address, Firefox copied contents of this file
into a temporary location and redirected user into this location, but not with the content protocol,
but with a file protocol. It's simply used to read local files. And what's important,
the name of the file in the temporary location remained unchanged. When defining those content URIs,
the application can specify directories that a user can open, but Firefox used the following configuration.
It means that the user can read any file that Firefox has access to. And among other configuration files,
inside Firefox directory, there is one that will be especially interesting for the attacker. It's
cookies.sql, which contains all cookies for a specific profile. Stealing those files would allow the attacker
to take over all the accounts to which he or she is currently logged in. But first, the attacker would
have to read profile's .ini file which would reveal the locations of cookie databases. So our goal will be stealing those files.
