always the case and that's exactly what allows HTTP request smuggling to happen. But when we have just one server
in such case even if it prioritizes the content length header this behavior is incorrect but it's far from
being a vulnerability. But in modern web applications we often have more than one server. At least there's a
front-end server also sometimes called a reverse proxy or a load balancer which just passes the request from
the server to the backend server also called application server and then the front-end server passes the
response back to the user. And what's important here is that now the stream of requests at the backend server
will have requests of multiple users which means if we can do something with this we can make much more
impactful actions. But how can we actually do this? Well now if we send both content length and transfer
encoding headers then if the front-end server will prioritize content length header and the backend server
will prioritize transfer encoding header then we can either prepend a part of our request to the request of another user
