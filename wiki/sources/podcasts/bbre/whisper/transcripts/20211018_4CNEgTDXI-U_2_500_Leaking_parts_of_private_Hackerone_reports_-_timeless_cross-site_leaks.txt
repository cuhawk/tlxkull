Let me show you how he achieved it.
HTTP requests are transmitted in TCP packets. You can think of it as the letters.
The HTTP request is the letter itself and TCP packet is the envelope. If your letter is long, it will be sent in multiple envelopes.
But if you have two short letters to the same address, you can send both of them in a single envelope.
So what you need to do is bundle both HTTP requests in a single TCP packet.
In case of an attack against the server without the client interaction, this is easy-peasy because you can write a low-level script that will do whatever you want.
But in this attack, we are in the browser and we have little control over low-level network protocols.
How do you then force the browser to send both letters in a single envelope?
The browser has built-in mechanism to prevent sending too many envelopes before the server acknowledges that they were received.
So the server will send as many envelopes as it can and the rest will be stored in the queue, waiting for the server to acknowledge receiving those sent envelopes.
Normally, the browser would envelope the first HTTP request straight away without waiting for the second one.
But when your two letters will be queued, they will be packed in a single envelope, which is exactly what we need.
But how do you force the browser to queue your requests?
By sending a big HTTP request first, which will be too big to be sent in one go.
Part of the request will be sent, but the remaining packets will be queued.
Part of the request will be sent immediately after you send your pair of requests, one with the baseline query and one with the query you are interested in.
Both of them will be added to the end of the queue.
After the server acknowledges that it received the first batch of packets, ones from the queue will be sent and your pair of HTTP requests will be bundled into a one TCP packet.
Part of the request will be sent in one of the requests.
Then you repeat the operation 20 times and you look how often the response with the query was second.
If it was second in about half of requests, your query did not return any reports.
If it was second in about 16 requests, that means that the string you are looking for is present in at least one of victim's reports.
You can move on to the next character or the next word.
This way it was possible to exfiltrate parts of private reports from HackerOne.
