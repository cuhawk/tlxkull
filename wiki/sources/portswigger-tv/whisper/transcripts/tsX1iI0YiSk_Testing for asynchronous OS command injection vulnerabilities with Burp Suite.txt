Hi. In this video, we'll take a look at using burp to test for asynchronous OS command injection
vulnerabilities. These vulnerabilities occur when the application is vulnerable to command
injection, but the command is executed asynchronously, meaning it has no noticeable impact on the
application's response. Burp collaborator can help you to test for these vulnerabilities by
using burp to inject a command that triggers an out-of-band network interaction with the
Burp collaborator server. Burp monitors the collaborator server to identify whether an
out-of-band interaction occurs, and therefore whether the command was executed. If you'd
like to follow along with this process, you can use the Blind OS command injection with
out-of-band interaction lab from our Web Security Academy. Once the lab has launched, investigate
the application and attempt to submit some feedback.
Go to the Proxy HTTP History tab and identify a request you want to investigate. In this
case, we'll look at the Submit Feedback request. Right-click the request and select Send to Repeater.
Now we're going to change the email parameter to a proof-of-concept payload. We're going to
use the NSLOOKUP command to cause a DNSLOOKUP for a collaborator subdomain. To insert a collaborator
subdomain into the payload, right-click and select Insert collaborator payload.
If an interaction with the collaborator server occurs, these will be listed on the collaborator tab,
which will also flash when an interaction occurs. Go to the collaborator tab, you may need to click
Poll Now and review any interactions that are listed in the table. You can repeat this process
to test any additional parameters. Make sure you continue to check the collaborator tab to
identify any delayed interactions.
