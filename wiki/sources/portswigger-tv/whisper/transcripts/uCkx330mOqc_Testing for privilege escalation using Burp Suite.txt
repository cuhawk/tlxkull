Hi. In this video, we'll look at how you can use Burp to test for privilege escalation.
When a user logs into an application, they usually only have access to the parts of the
application they need to perform their specific tasks.
If access controls are incorrectly set, a user can gain access to functionality that
should only be available to higher privileged users.
If you have credentials for both high and low privileged accounts, you can test the effectiveness
of an application's access controls by accessing the application using different accounts.
You can use Burp to send ad hoc requests to compare access, or automate the steps for sending
multiple requests as a different user.
If you'd like to follow along, you can use the lab Method-Based Access Control can be circumvented
from our Web Security Academy.
Before you start, make sure you have credentials for both a high privileged or admin account,
and a low privileged user.
Once we have this, we can use Burp to send ad hoc requests to a specific endpoint.
So first, log in as the administrator, visit the admin page, and log out.
Now, go back to the login page, and log in again as the low privileged user.
To test a specific endpoint, we'll head to the proxy HTTP history tab.
Find the admin panel request sent by the high privileged user, right click, and send it to
the repeater tab.
Before we switch over to the repeater tab, find the low privileged user's most recent request,
and copy the session cookie.
Now it's time to switch to the repeater tab.
We can edit the request we sent to the tab earlier, and paste in the low privileged user's
cookie to replace the original session cookie.
Click send.
Now, review the response to identify if privilege escalation was possible.
In this case, we're getting a 401 unauthorized response, so we have not been able to escalate
the privileges.
If we needed to do this for a large number of requests, this could be time consuming.
So we can use Burp to automate this process across all requests in the current sitemap.
The first step is to make sure you have mapped the application as a high privileged user.
If you're using the lab, make sure you visit the admin page.
Once you've mapped the application, log out and log back in again as the low privileged
user to obtain their session cookie.
Find this user's most recent request in the proxy HTTP history tab and copy the session cookie.
Now we can create a session handling rule to add the low privileged user's session cookie
to all requests sent from the target tool.
To do this, go to Settings, then to Sessions, Session Handling Rules, and click Add.
Go to the Scope tab, and under the Tools scope, select Target and deselect all other tools.
Next, under URL scope, select Use custom scope, and click Add or Paste URL to add your target
URL.
Now switch back to the Details tab to define the rule.
Under Rule Actions, click Add, then select Set a specific cookie or parameter value.
Add in the cookie name, and in value, paste in the cookie you copied from your low privileged
user's request.
Keep clicking OK to close all open dialogs.
The rule will be added to the list of session handling rules.
We can now easily re-request the entire site map as a low privileged user.
Go to Target, Sitemap, right click the target host, and select Compare sitemaps.
Select Use current sitemap, and click Next.
Select Use only selected branches.
